This artifact defines a brand and visual-language foundation for the REIS OS Command. It does not create runtime authority, implementation authority, promotion authority, or Atlas data dependencies.

## Product identity

```text
REIS OS COMMAND
= FOUNDER-EXCLUSIVE INSTITUTIONAL EXPERIENCE
= OPERATIONAL OBSERVATORY + CONTROL SURFACE
!= COMMERCIAL PRODUCT UX
```

The Command must feel like the living institutional surface of REIS OS: precise, evidence-aware, operational, calm under complexity, and explicit about epistemic state.

## Brand principles

1. **Institutional before decorative** — every visual decision must improve interpretation, orientation, trust, or action readiness.
2. **Complexity with legibility** — dense systems are allowed; ambiguity is not.
3. **Evidence has visual weight** — claims, receipts, assurance, freshness, and provenance must be perceptually distinguishable.
4. **Authority is never implied by aesthetics** — emphasis, color, iconography, or placement cannot manufacture authority.
5. **State is semantic** — PASS, HOLD, NOT_PROVEN, NOT_AUTHORIZED, DEGRADED, STALE, CONFLICT, and UNKNOWN require distinct treatments.
6. **Founder confidence over marketing persuasion** — the interface exists to support reading and decision, not conversion.
7. **REIS OS identity over generic admin-dashboard language** — naming and tone should remain institutional and specific.

Rules:

```text

STALE != CURRENT
UNKNOWN != ZERO
```

Each state must combine at least two channels where material: label + shape/icon; label + border/pattern; label + position; or label + temporal/freshness marker.

## Tone of voice

The Command voice is:
- concise;
- institutional;
- explicit about uncertainty;
- non-promotional;
- causally precise;
- resistant to false completion;
- readable under operational stress.

Preferred formulations:
- `Assurance pending`
- `Evidence incomplete`
- `Current state verified at <time>`
- `Founder approval required`
- `No causal proof available`
- `Runtime not authorized`

Avoid formulations that collapse state:
- `Everything looks good`
- `Done` when only requested or proposed;
- `Safe` without scope/evidence;
- `Approved` without authority source.

## Visual personality

The target personality is:

```text
TECHNICAL
+ INSTITUTIONAL
+ CONTROLLED
+ HIGH-INFORMATION
+ EVIDENCE-AWARE
+ NON-DECORATIVE
+ DISTINCTIVE
```

The system may be visually sophisticated, but should avoid ornamental complexity that does not map to structure, hierarchy, state, causality, evidence, or action readiness.

## Typography principles

Typography must support:
- dense operational reading;
- stable numerical alignment;
- clear distinction among headline, state, metadata, evidence, and code/identifier content;
- long mobile sessions;
- Android-first rendering.

Specific font-family selection remains a later visual-design decision; this contract freezes functional requirements, not a font brand.

## Iconography principles

Icons must represent functional categories, not emotional decoration.

Families to support:
- state;
- risk;
- evidence;
- assurance;
- authority;
- recovery;
- causality;
- OCS identity;
- integration;
- freshness/time;
- graph structure.

No icon may be the sole carrier of a critical state.

## Trust and authority cues

Trust is built through:
- visible source/freshness context;
- stable state labels;
- explicit authority boundaries;
- evidence access;
- consistent terminology;
- reversible drill-down;
- no hidden state upgrades.

```text
SIGNAL_OF_TRUST != AUTHORITY
VISUAL_PROMINENCE != PROMOTION
BRAND_CONFIDENCE != ASSURANCE
```
